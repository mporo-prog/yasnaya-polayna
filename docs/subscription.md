# Подписка из финального экрана

Игра размещается на `https://game.ypmuseum.ru/`, обработчик заказчика —
`https://ypmuseum.ru/request/subscribe`. На 29 сентября 2026 года ответы
главной страницы и OPTIONS обработчика не содержат заголовков CORS.
Поэтому прямой `fetch` между этими двумя доменами не используется.

## Настройка сервера игры

На HTTPS-сервере `game.ypmuseum.ru` подключить
[`deploy/subscription.nginx.conf`](../deploy/subscription.nginx.conf)
внутри существующего `server {}`. Администратор должен проверить конфигурацию
через `nginx -t` и применить её обычным способом на этом сервере.
Из репозитория настройки удалённого сервера не применяются.
Для другого веб-сервера нужны те же два точных маршрута:

| Адрес на домене игры | Метод | Адрес основного сайта |
| --- | --- | --- |
| `/request/subscribe-session` | GET | `https://ypmuseum.ru/` |
| `/request/subscribe` | POST | `https://ypmuseum.ru/request/subscribe` |

Прокси передаёт `Set-Cookie` и последующие `Cookie`, заменяет cookie Domain
`ypmuseum.ru` на `game.ypmuseum.ru`, выставляет upstream Host/Origin/Referer
для основного сайта и не кэширует ответы. Перед заменой Origin POST проверяется
исходный Origin `https://game.ypmuseum.ru`. CSRF-проверка основного сайта остаётся
включённой. Нельзя кэшировать HTML с токеном, фиксировать `_csrf` в исходниках
или подставлять один общий токен всем игрокам.

В `npm run dev` аналогичные маршруты предоставляет Vite. При `npm run build`
они **не превращаются в сервер**: на хостинге по-прежнему нужна указанная
конфигурация. Сборка включает отдельную страницу `games/finish/index.html`;
переход игрового сюжета к финалу в рамках этой формы не менялся.

## Поведение формы

- Клик по конверту или Enter в поле запускает отправку.
- Пустой/некорректный адрес не отправляется; края строки обрезаются.
- Перед запросом берётся `meta[name=csrf-token]` текущего документа,
  либо загружается `/request/subscribe-session` для получения токена и cookie.
- POST отправляет `email` и `_csrf` в `application/x-www-form-urlencoded`,
  как исходная jQuery-форма. Email не сохраняется в localStorage или логах.
- `error: 0` — просьба проверить почту и подтвердить подписку;
  `error: 11` — «Вы уже подписаны. Спасибо!»; остальные коды — текст сервера.
- HTML из сообщения сервера не исполняется. При ошибке сети/таймауте показано
  сообщение о недоступности. Успех показывается только после ответа сервера.
- Во время запроса повторная отправка заблокирована. Таймаут — 15 секунд;
  автоматических повторов POST нет. При выходе из сцены запрос отменяется.
- Если доступна `window.yp.ga.event`, сохраняется исходное событие
  `Footer / click_footer_subscribe_email`; отсутствие аналитики не мешает форме.

## Проверка

`npm test` проверяет контракт запросов и ответы на подставном сервере.
`tests/finish-subscription.html` проверяет интерфейс с подставными ответами;
эта страница не отправляет email и не включена в production-сборку.

Перед запуском на хостинге проверить получение сессионного токена, затем
подписку на **согласованный тестовый адрес** и получение письма подтверждения.
При разработке реальные подписки не создавались. Получение письма не может
подтвердить один только успешный локальный тест.

В текущей среде проверены доступность основной страницы, наличие CSRF-meta и
отсутствие CORS. Пробный GET через локальный Vite-прокси получил сетевой таймаут
при подключении Node.js к внешнему сайту; цепочку прокси с живым сервером
не удалось подтвердить. После настройки хостинга требуется указанная проверка.
