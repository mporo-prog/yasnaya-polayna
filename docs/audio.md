# Настройки звука и подключение аудио

Экран доступен через «Настройки» в главном меню и меню паузы.
Три ползунка принимают целые значения 0–100, по умолчанию 50.
«Сохранить» применяет громкость ко всем зарегистрированным звукам
и сохраняет её в `localStorage` под ключом `vn_audio_settings_v1`.
«Назад» и Esc закрывают экран, отменяя изменения после последнего сохранения.
Клавиши ↑/↓ или Tab выбирают ползунок, ←/→ меняют значение на 1,
Home/End устанавливают 0/100.

| Ползунок | Папка относительно `public/resource/sound` | Категория |
| --- | --- | --- |
| Громкость музыки | `music` | `music` |
| Громкость звуков | `ui` | `ui` |
| Громкость голоса | `voice_and_sound` | `voice` |

Категория определяется по папке, включая вложенные папки. Перечень имён
файлов не нужен. Настройки отделены от сюжетного прогресса, поэтому его
сброс не сбрасывает громкость. Старые неиспользуемые поля громкости
в `GameState.state.settings` не участвуют в управлении аудио.

## Музыка и звуки в параметрах сцен

Контроллер `public/resource/systems/MusicController.js` использует встроенный
Web Audio API (`AudioBufferSourceNode`, `GainNode`), без Howler и других аудиобиблиотек.
Phaser предоставляет существующий `AudioContext` и кэш декодированных записей.
`SceneAudio.js` связывает контроллер с параметрами и жизненным циклом сцен.

Аудио задаётся в двух файлах:

- `public/resource/data/story/storyAudio.js` — массив сюжетных сцен в том же
  порядке, что `storyBackgrounds`. Вложенный `screens` соответствует экранам сцены.
- `public/resource/data/sceneAudio.js` — объекты меню и мини-игр по ключам Phaser.

Сейчас в этих файлах стоят пустые параметры: в проекте есть только тестовые записи,
они не назначены сюжету автоматически. Например, первый объект в `storyAudio.js`
можно заполнить существующими файлами так:

```js
{
  music: { path: 'music/test_music.mp3', volume: 0.8, loop: true },
  transition: {
    type: 'crossfade',
    fadeOutDuration: 2,
    fadeInDuration: 3,
    fadeOutDelay: 0,
    fadeInDelay: 0.5,
  },
  // Для настоящего перехода замените тестовый файл на короткий эффект.
  transitionSound: { path: 'ui/ui_sound_test.mp3', volume: 0.6, delay: 0.2 },
  sounds: [], // Проигрываются один раз при входе в сцену.
  screens: [
    { sounds: [{ path: 'voice_and_sound/test_voice.mp3', volume: 1 }] },
    { sounds: [] },
    { music: null, transition: { type: 'fadeout', duration: 1.5 }, sounds: [] },
  ],
}
```

Пути задаются относительно `public/resource/sound`. Вместо объекта звука можно
использовать строку пути. Для музыки по умолчанию `loop: true`, для `sounds` —
`false`, громкость файла `volume` — 1. У обычных звуков также есть `delay` и `loop`.

**Все длительности и задержки — в секундах**, допустимы дробные значения и 0.
Отрицательные, бесконечные и строковые значения отклоняются.

| Тип `transition` | Параметры | Поведение при смене музыки |
| --- | --- | --- |
| `fadeout` | `duration: 1`, `delay: 0` | Старый трек затухает, затем новый запускается с полной громкостью. |
| `fadein` | `duration: 1`, `delay: 0` | Старый трек останавливается, новый появляется плавно после задержки. |
| `crossfade` (по умолчанию) | `fadeOutDuration: 1`, `fadeInDuration: 1`, `fadeOutDelay: 0`, `fadeInDelay: 0` | Два независимых фейда, допускающие перекрытие или паузу. |

Обе задержки crossfade отсчитываются **от начала перехода**, а не друг от друга.
Новый файл начинает воспроизводиться с начала в момент `fadeInDelay`.
Например, `fadeOutDuration: 2, fadeOutDelay: 0, fadeInDelay: 2.5` оставляет
полсекунды тишины между фейдами. `transitionSound.delay` также отсчитывается
от входа в сцену/экран и не зависит от фейдов.

- `music: null` плавно выключает музыку; без поля `music` текущая музыка сохраняется.
- Экран может переопределить `music`, `transition`, `transitionSound` и `sounds`.
  Его музыка действует до следующего явного указания `music`.
- Одинаковый путь текущей музыки не перезапускается. Для намеренного повтора
  укажите `restart: true` в объекте музыки или перехода.
- При переходе Back или загрузке сохранения восстанавливается музыка нужного
  экрана. Звуки пропущенных экранов не воспроизводятся. Повторная отрисовка того
  же экрана не запускает аудио заново; реальное возвращение на экран запускает его эффекты.
- Звуки `sounds` сцены останавливаются при её закрытии. Звуки экрана — при смене
  экрана или закрытии сцены, включая ещё не начавшиеся отложенные записи.
- Музыка и звук перехода переживают закрытие сцены. Следующий переход отменяет
  предыдущий переходный эффект; отложенный музыкальный трек отменённой сцены
  не запустится позднее. Завершённые источники и узлы освобождаются.
- Пауза и настройки продолжают текущую музыку. Скрытие вкладки обрабатывает
  общий аудиоконтекст Phaser, поэтому фейды следуют за его аудиочасами.

В основной игре загрузка настроенных файлов уже подключена к `BootScene`,
а обработчики — к меню, сюжетным сценам и мини-играм. Для новой Phaser-сцены:

```js
preload() {
  window.VN.systems.SceneAudio.preload(this);
}

create() {
  this.sceneAudio = window.VN.systems.SceneAudio.enter(this);
}

// Если у сцены есть собственные экраны:
showScreen(index) {
  this.sceneAudio.showScreen(index);
}
```

Конфигурацию можно передать вторым аргументом `preload/enter`, либо через
`this.scene.start('GameScene1', { audio: { music: 'music/test_music.mp3' } })`.
Параметр `audio` полностью заменяет конфигурацию из файла данных для этого запуска.

## Прямое управление переходами

Если переход запускается игровым событием, получите общий экземпляр:

```js
const music = window.VN.systems.MusicController.forScene(this);

music.fadeOut({ duration: 2, delay: 0.3 });
music.fadeIn('music/test_music.mp3', { duration: 3, volume: 0.8 });
music.crossfade('music/next-theme.mp3', {
  fadeOutDuration: 2,
  fadeInDuration: 3,
  fadeOutDelay: 0,
  fadeInDelay: 0.5,
});
music.playTransition('ui/transition.mp3', { volume: 0.6, delay: 0.2 });
```

Вызовы выше — отдельные примеры, не последовательность для копирования целиком.
Файлы должны быть загружены в `preload` через `AudioManager.load` или `SceneAudio.preload`.
При прямом вызове ошибка отсутствующего файла выбрасывается до остановки старой музыки.
`SceneAudio` выводит её в консоль и позволяет сцене продолжить работу.

`playSound(path, { volume, delay, loop })` запускает обычный эффект и возвращает
объект с `stop()` и `setVolume(value)`. Такой эффект при прямом использовании
останавливает его владелец. `playTransition` всегда проигрывает файл один раз,
а `playTransition(null)` отменяет текущий переходный эффект.
`stop()` сразу останавливает музыку и все эффекты контроллера. `destroy()` также
освобождает ресурсы контроллера; в основной игре он вызывается при уничтожении игры.
Не вызывайте эти методы в `shutdown` каждой сцены: это оборвёт crossfade.

Контроллер можно перенести из Phaser: передайте в конструктор `{ context,
destination, getBuffer, audioManager }`. `getBuffer(path)` должен синхронно вернуть
заранее декодированный `AudioBuffer`, а `audioManager.registerGain(path, node, volume)` —
подписку с `setVolume(value)` и `destroy()`. В игре используется существующий
`AudioManager`. Новый `AudioContext` на каждый переход не создаётся; разблокировку
звука после пользовательского действия выполняет Phaser.

## Совместимость с громкостью

Звуковой граф нового контроллера:

```text
AudioBufferSource → громкость файла × настройка категории → коэффициент фейда
                 → глобальные mute/volume Phaser → динамики
```

Громкость музыки, звуков и голоса продолжает определяться папкой файла.
Настройки и коэффициент фейда находятся в разных `GainNode`, поэтому сохранение
громкости во время перехода не сбрасывает фейд. Нулевая громкость категории
остаётся нулевой при любом переходе. Структура и ключ `localStorage` не изменены.

## Существующие Phaser-звуки

Прослушать три тестовые записи можно через «Режим разработчика → Саундтест».
На этом экране ползунки сохраняют общую громкость автоматически при изменении,
а кнопки записей переключают воспроизведение и остановку.
Для подключения используйте общий `VN.systems.AudioManager`. Пример:

```js
preload() {
  const audio = window.VN.systems.AudioManager;
  audio.load(this, 'music/test_music.mp3');
  audio.load(this, 'ui/ui_sound_test.mp3');
  audio.load(this, 'voice_and_sound/test_voice.mp3');
}

create() {
  const audio = window.VN.systems.AudioManager;
  // Запускать в нужном игровом событии после пользовательского действия.
  this.music = audio.play(this, 'music/test_music.mp3', { loop: true });
  audio.play(this, 'ui/ui_sound_test.mp3');
  audio.play(this, 'voice_and_sound/test_voice.mp3');

  this.events.once('shutdown', () => this.music.destroy());
}
```

Пути задаются относительно `resource/sound`. URL строится от местоположения
модуля и учитывает размещение игры в `/yasnaya-polayna/`.
`load` вызывается в `preload`, `play` — после завершения загрузки.
Одноразовые звуки освобождаются после окончания. Зацикленные звуки
и остановленные до окончания экземпляры нужно удалять через `destroy()`.
Для повторного использования одного экземпляра есть `audio.add(scene, path, config)`;
он возвращает Phaser Sound, который можно запускать через `sound.play()` без аргументов,
приостанавливать через `pause()`, продолжать через `resume()` и удалять через `destroy()`.

Итоговая громкость = индивидуальная громкость файла × процент категории / 100.
Индивидуальный уровень задаётся через `config.volume` (0–1) при `add/play`
или через `audio.setVolume(sound, value)` позже. Например, 0.8 × 50% = 0.4.
Нулевое значение категории всегда даёт 0; повторное сохранение не накапливает затухание.
Применение обновляет также приостановленные звуки и учитывается при следующем запуске.

Для сохранения этой связи подключайте файлы через менеджер и меняйте индивидуальную
громкость через `audio.setVolume`, а не напрямую через `sound.setVolume`,
`sound.play({ volume: ... })`, `this.sound.play` или `new Audio()`.
Отдельные страницы мини-игр при самостоятельном запуске должны подключить
`namespace.js` и `AudioManager.js`; в общей игре они уже подключены в `index.html`.

Для отдельно запускаемых мини-игр новое аудио также требует подключения
`MusicController.js`, `SceneAudio.js` и при необходимости файлов аудиоданных
после `namespace.js` и `AudioManager.js`, до создания сцен. Их необязательные
вызовы сохраняют возможность запуска старых отдельных страниц без аудиопараметров.

## Проверка

`npm test` проверяет настройки, музыкальные переходы, задержки, отмену старых
источников, жизненный цикл сцен и режим разработчика. `npm run build` проверяет сборку.

Для проверки настоящего браузерного Web Audio API запустите `npm run dev` и
откройте `/yasnaya-polayna/tests/audio-offline.html`. Четыре проверки на
`OfflineAudioContext` сравнивают реальные отсчёты двух аудиоканалов: crossfade,
отмену отложенного трека, изменение громкости и прерывание незавершённого фейда.
Звук в динамики не выводится, исходные настройки восстанавливаются после проверки.
