# Загрузка ресурсов сцен

`BootScene` запускает невидимую `AssetLoaderScene`, затем меню или мини-игру
из параметра `?game=1…5`. Все игровые сцены используют одну очередь и общие
кеши Phaser. Служебная сцена остаётся активной при паузе, настройках и переходах
через режим разработчика.

`BootScene` не загружает медиа всей игры. Сразу после получения HTML виден
экран «Запускаем игру…», которому не нужны Phaser, картинки или внешние шрифты.
CSS Google Fonts подключается без блокировки первого экрана; после готовности
шрифтов текстуры текста Phaser обновляются. Когда начинает
загружаться меню (или мини-игра из `?game=`), HTML-индикатор показывает долю
готовых ресурсов этой сцены. Он исчезает после её первого отрисованного кадра.

## Маршрут

- Меню ждёт свой фон и текстуры кнопок. После создания оно загружает музыку и первую
  сюжетную сцену. Поздно загрузившаяся музыка не включается после ухода из меню.
- Сюжет загружает только свои фоны, портреты участвующих персонажей, иконки и
  звуки. Во время показа готовится следующая мини-игра.
- Мини-игра готовит следующий сюжетный фрагмент; последняя — главное меню.
- Предзагрузка не запускает сцену, её звук, таймеры или игровую логику.

`SceneAssets.preload(scene)` добавляет в обычный загрузчик Phaser барьер:
`create()` вызывается только после готовности ресурсов, включая декодирование
аудио. Если игрок перешёл раньше, показывается «Загрузка… N%». Процент отражает
количество завершённых файлов, а не байты. Обновление происходит после каждого
обработанного файла, включая декодирование, а не после всей партии. При попадании
в кеш экран ожидания перехода не создаётся. Искусственных задержек для показа
процентов нет: при быстром соединении меню может появиться сразу.

`AssetQueue` объединяет фоновые и обязательные запросы по типу и ключу.
Загрузка идёт партиями до четырёх файлов; ещё не начатые ресурсы текущего
перехода получают приоритет. Уже начатые запросы не отменяются при переходах.
Остановка ожидающей сцены отменяет только её ожидание, а не общую загрузку.

Сетевой запрос ограничен 15 секундами. Ошибки сети и декодирования не оставляют
очередь навсегда занятой. Неудачная предзагрузка может быть повторена при входе;
готовые файлы повторно не загружаются. Для отсутствующих сюжетных фонов остаётся
существующий экран-заглушка, для звуков — существующая обработка ошибок SceneAudio.
В текущих данных сцены 2–6 всё ещё ссылаются на отсутствующие JPG: теперь эти
запросы выполняются перед соответствующей сценой, а не при открытии сайта.

## Добавление ресурсов

Фоны, реплики, портреты и аудио сюжета берутся из существующих `VN.data`.
Текстуры интерфейса меню и сюжета, картинки и дополнительные звуки мини-игры
описываются в методе соответствующей сцены. `key` должен совпадать с ключом,
переданным в `add.image()` или `textures.get()`; одного файла в `public` недостаточно.
Например, `dialogTextBg` загружается из `images/icon_UI/dialog_text_bg.webp`.

Пример объявления:

```js
getAssetManifest() {
  return {
    images: [{ key: 'table', url: `${import.meta.env.BASE_URL}images/table.webp` }],
    audio: ['voice_and_sound/example.mp3'],
  };
}
```

В `preload()` вызывается `VN.systems.SceneAssets.preload(this)`, а в конце
`create()` — `VN.systems.SceneAssets.prefetchNext(this)`. Для отдельных страниц
мини-игр сохранена обычная загрузка, если SceneAssets не подключён.
При добавлении нового типа мини-игры нужно также добавить его ключ в
`SceneAssets.nextTarget`, чтобы он готовил следующую сюжетную сцену.

Файлы скачиваются с `?v=<хэш содержимого>`, чтобы долгий кэш хостинга не
отдавал игрокам старые версии (см. `docs/caching.md`).

Кнопка «Начать» сбрасывает прогресс и открывает сюжет 0/0.
Меню предзагружает первую сюжетную сцену независимо от сохранения.

## Проверка

Для проверки первого экрана на медленной сети: `npm run build`, затем
`node tests/serve-slow-startup.mjs`. Открыть
`http://127.0.0.1:4174/yasnaya-polayna/tests/startup-loading.html`.
Сервер задерживает движок, три картинки меню и CSS шрифтов независимо друг от друга.
Проверка подтверждает ранний HTML-экран, промежуточные 33% и 67%, отсутствие
загрузки остального контента до меню и скрытие индикатора после готовности меню.

`npm test` проверяет кеш, приоритеты, пересечение запросов, остановку сцен,
ошибки и позднюю музыку. `npm run build` проверяет сборку для GitHub Pages.
При запущенном `npm run dev` откройте
`/yasnaya-polayna/tests/asset-loading.html`: это отдельная тестовая игра с
реальным Phaser 3.80.1, управляемой задержкой фоновой загрузки и декодированием
звука. Тест не меняет прогресс или настройки основной игры.
`/yasnaya-polayna/tests/site-loading.html` дополнительно проверяет настоящий
маршрут, все мини-игры, возврат в меню и холодный запуск `?game=1…5` во фрейме;
исходное сохранение восстанавливается после проверки.

Схема сборки JS сохранена.
Загруженные ресурсы остаются в кеше до закрытия игры.

## Форматы файлов

Картинки хранятся в WebP, звук — в MP3, анимация портрета — в WebM с запасным MP4
(см. `docs/story-portrait.md`). Новые PNG и WAV перед подключением конвертируются FFmpeg:

```powershell
# Фоны, персонажи и другие крупные картинки (при заметных артефактах — 90–94)
ffmpeg -i in.png -vf format=bgra -c:v libwebp -quality 85 -compression_level 6 -map_metadata -1 out.webp
# Мелкие элементы интерфейса с ровными заливками — без потерь
ffmpeg -i in.png -vf format=bgra -c:v libwebp -lossless 1 -quality 100 -compression_level 6 -map_metadata -1 out.webp
# Звук
ffmpeg -i in.wav -map_metadata -1 -c:a libmp3lame -q:a 2 out.mp3
```

WebP сохраняется без цветового профиля. PNG с профилем Display P3 (экспорт с Mac)
перед кодированием переводятся в sRGB, иначе цвета станут бледнее — в `-vf` вместо
`format=bgra`:
`format=gbrapf32le,zscale=primariesin=smpte432:transferin=iec61966-2-1:matrixin=gbr:rangein=full:primaries=bt709:transfer=iec61966-2-1:matrix=gbr:range=full,format=bgra`.

MP3 содержит заголовок LAME с задержкой энкодера; Chrome отрезает её при
декодировании, поэтому длина звука совпадает с WAV и зацикленная музыка не получает
паузы на стыке. Три WAV совпадали по имени с другими, уже существующими MP3-записями,
и получили суффикс `_alt`: `voice_and_sound/gameplay1_rasskazchik_alt.mp3`,
`voice_and_sound/screen_1_1_scene_2_posetitel3_alt.mp3`,
`voice_and_sound/scene2_gameplay2/screen_1_1_scene_2_posetitel3_alt.mp3`.
