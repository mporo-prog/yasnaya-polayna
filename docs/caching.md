# Кэш на хостинге и обновление файлов у игроков

## Почему это нужно

На хостинге (REG.RU) перед Apache стоит nginx. Скрипты `resource/*.js`, стили,
картинки, MP3 и видео nginx отдаёт сам с `Cache-Control: max-age=3888000`
(45 дней), `.htaccess` на них не действует. HTML отдаёт Apache без
`Cache-Control`, и браузер держит страницу в кэше «на глазок».

Vite хэширует имена только у собранного бандла (`assets/main-*.js`). Файлы из
`public/` выкладываются под прежними именами. Без мер ниже вернувшийся игрок до
45 дней получал старые скрипты, картинки и звук вперемешку с новым бандлом.

## Как устроено

1. **HTML не кэшируется.** `public/.htaccess` отдаёт `*.html` с
   `Cache-Control: no-cache`, и браузер сверяет страницу при каждом входе.
   Из-за сжатия gzip Apache хостинга отвечает не 304, а полной страницей.
   Это около 3 КБ.
2. **Ссылки в HTML версионируются при сборке.** Плагин `build/assetVersions.js`
   добавляет к ссылкам на файлы `public/` в `index.html` и
   `games/finish/index.html` параметр `?v=` с хэшем содержимого. Например:
   `resource/systems/Layout.js?v=f0ed62e934`. Изменённый файл получает новый
   адрес и скачивается заново. Неизменённые файлы остаются в кэше.
3. **Адреса, которые игра собирает сама, версионируются при загрузке.** Плагин
   кладёт в сборку таблицу «путь → хэш» (`assets/asset-versions-*.js`) и
   подключает её прямо перед первым скриптом игры.
   `VN.systems.AssetVersions.url()` (`public/resource/systems/AssetVersions.js`)
   добавляет `?v=` к картинкам, звуку и видео. Он подключён в
   `AssetLoaderScene`, `AudioManager.load`, видео портрета в `StoryScene` и
   `FinishScene`. Ключи текстур и звуков не меняются: Phaser по-прежнему
   находит их по пути к файлу.

В `npm run dev` таблицы нет, и адреса остаются без `?v=`.

## Что делать при разработке

- Новые файлы в `public/` и новые `<script src="resource/...">` в HTML
  версионируются автоматически.
- Новый код, который скачивает файл в обход `SceneAssets`/`AudioManager.load`,
  должен передавать адрес через
  `window.VN.systems.AssetVersions?.url(url) ?? url`.
- Ссылки `url(...)` внутри CSS-файлов из `public/` не версионируются. Сейчас
  таких ссылок нет.

## Выкладка

Загружать всю папку `dist`, включая `assets/` и `.htaccess`, **в два шага**:

1. Сначала всё, кроме HTML: `assets/`, `resource/`, `images/`, `video/`,
   `.htaccess`, `robots.txt`.
2. Когда первый шаг полностью закончен — `index.html`, `games/finish/index.html`
   и `games/game2/index.html`.

Почему так: сервер не смотрит на `?v=` и отдаёт тот файл, который сейчас лежит
на диске. Если новый HTML окажется на сервере раньше новых файлов, игрок,
открывший игру в эти минуты, получит по новому адресу старый файл. Браузер
сохранит его на 45 дней. Старые файлы из `assets/` удалять не нужно, пока
новый HTML не выложен.

После выкладки проверить:

```bash
curl -sI https://game.ypmuseum.ru/ | grep -i cache-control
```

Ответ должен содержать `Cache-Control: no-cache`, а в исходном коде страницы у
ссылок на `resource/...` должен стоять `?v=`.

Игроки, у которых старая страница ещё лежит в кэше «на глазок», получат новую
при следующей проверке браузером. Это занимает от нескольких часов до
нескольких дней в зависимости от возраста прошлой выкладки. Дальше страница
сверяется при каждом входе. Вкладка, открытая во время выкладки, работает со
старыми скриптами до перезагрузки. Картинки и звук, которые она загрузит уже
после выкладки, могут прийти новые. Перезагрузка страницы всё исправляет.

Проверки: `npm test` (`tests/asset-versions.test.js` собирает проект с базой `/`,
как на продакшене, и сверяет хэши с файлами `public/`).
